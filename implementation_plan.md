### Recomendação: **Vite (Vanilla — HTML/CSS/JS)**

**Justificativa:**

1. **Alinhamento com o conhecimento atual** — Felipe tem experiência com HTML, CSS e JavaScript. Um portfólio vanilla bem executado demonstra domínio dos fundamentos, que é o que recrutadores de vagas júnior procuram.

2. **SEO nativo** — HTML estático é o melhor cenário possível para SEO. Sem necessidade de SSR, hydration ou configurações adicionais.

3. **Performance máxima** — Zero runtime JavaScript de framework. O site carrega instantaneamente.

4. **Deploy simples** — GitHub Pages diretamente do repositório. Zero custo, zero configuração.

5. **Facilidade de manutenção** — Sem dependências de framework para atualizar. Sem breaking changes de versão.

6. **Vite como bundler** — Oferece hot reload, build otimizado e module bundling sem o peso de um framework. É a ferramenta de build moderna por excelência.

7. **O portfólio como prova de conceito** — Um portfólio vanilla bem feito, com animações suaves, responsividade perfeita e boa arquitetura de CSS demonstra que o desenvolvedor domina os fundamentos — React e Next.js ele pode demonstrar nos projetos individuais.

> [!NOTE]
> Se depois o Felipe quiser migrar para um framework (por exemplo, para adicionar um blog com MDX ou páginas dinâmicas de projeto), a migração de Vite vanilla para Astro é relativamente simples, pois ambos usam Vite como base.

## 11. Estratégia de Responsividade

### Abordagem: Mobile-First

Todo o CSS será escrito para mobile primeiro, com breakpoints progressivos para telas maiores.

### Breakpoints

| Breakpoint | Alvo | Comportamento |
|-----------|------|---------------|
| Default (< 640px) | Celular | Layout em coluna única, nav com hamburger |
| `640px` | Celular grande / tablet portrait | Ajustes de padding, grid 2 colunas para cards |
| `768px` | Tablet | Grid de projetos 2 colunas, "Sobre mim" lado a lado |
| `1024px` | Notebook / tablet landscape | Navbar expandida, grid 3 colunas |
| `1280px` | Desktop | Layout completo, espaçamentos generosos |

### Decisões de layout por breakpoint

**Mobile (< 640px):**
- Hamburger menu com overlay
- Hero em coluna única
- Cards de projeto em coluna única, full-width
- Stack técnica em lista vertical
- Timeline de experiência simplificada

**Tablet (768px–1023px):**
- Navbar parcialmente expandida
- Grid de projetos 2 colunas
- "Sobre mim" com texto e dados lado a lado

**Desktop (1024px+):**
- Navbar completa com todos os links visíveis
- Grid de projetos 2-3 colunas
- Layout generoso com whitespace

### Princípios

- Testes em **dispositivos reais** (não apenas resize do browser)
- Touch targets mínimo de **44x44px** em mobile
- Texto nunca menor que **14px** em qualquer dispositivo
- Imagens responsivas com `srcset` quando necessário
- Container com `max-width: 1200px` e `margin: 0 auto`

## 13. Estratégia de Acessibilidade

### Nível alvo: WCAG 2.1 AA

| Área | Implementação |
|------|--------------|
| **Contraste** | Mínimo 4.5:1 para texto normal, 3:1 para texto grande. Testar ambos os temas. |
| **Navegação por teclado** | Tab order lógico, focus ring visível, skip-to-content link |
| **Leitores de tela** | Landmarks semânticos, aria-labels em ícones, alt text em imagens |
| **Animações** | Respeitar `prefers-reduced-motion`, desabilitar animações quando solicitado |
| **Touch targets** | Mínimo 44x44px em elementos interativos |
| **Texto** | Não usar imagem como texto, font-size em rem, zoom até 200% sem quebrar layout |
| **Links** | Texto descritivo (não "clique aqui"), distinguíveis do texto ao redor |
| **Formulários** | Labels associados, mensagens de erro descritivas |
| **Tema** | Respeitar `prefers-color-scheme` do sistema como padrão |

### Implementação específica

```css
/* Skip to content */
.skip-link { /* visível apenas no focus */ }

/* Respeitar preferência de movimento */
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}

/* Focus ring visível e estilizado */
:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }
```
